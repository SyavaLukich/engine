# Бенчмарк

Запуск: `./build.sh bench` (сначала тесты, затем бенчмарк). Исходник: `bench/BenchMain.pas`.

## Методика

- Сборка: `-O3 -Xs`, по умолчанию `-OpCOREAVX2 -CfAVX2` (Haswell и новее). Для переносимой сборки без AVX2: `FPC_CPU_OPTS="" ./build.sh bench`.
- Один поток. Фиксированный `RandSeed = 2026`, поэтому входные данные одинаковы от прогона к прогону.
- Таймер: `GetTickCount64`. Разрешение 1 мс на Linux и около 16 мс на Windows, поэтому каждый замер длится не меньше 0.5 с.
- Стенд: виртуальная машина, 2 vCPU Intel Xeon 2.6 GHz, FPC 3.3.1-dev, x86_64, Linux. Числа зависят от железа и не отражают современные настольные процессоры.
- Разброс: два прогона на одном стенде отличаются на 1-3 %.

## Результаты

Колонка «AVX2» - сборка по умолчанию. Колонка «baseline» - `FPC_CPU_OPTS=""`, x86-64 без расширений.

|---|---|---|

| Бокс-бокс, только GJK | 1.99 мкс/пара | 2.11 мкс/пара |
| Бокс-бокс, GJK + EPA (контакт) | 7.94 мкс/пара; 3.0 итераций GJK и 7.5 итераций EPA | 7.87 мкс/пара |
| Выпуклая оболочка 20 точек, GJK + EPA | 11.7 мкс/пара | 11.7 мкс/пара |

## Выводы

- Флаги AVX2 на этом коде не дают измеримого выигрыша: разница в пределах шума. Код скалярный и ветвистый, основное время в GJK и EPA.
- Узкое место - плотные стопки. 400 тел при шаге 1/240 с занимают около 4.7 мс на шаг, то есть примерно 1.1 с процессорного времени на 1 с моделируемого времени в один поток. Это медленнее реального времени на этом стенде. Основная часть уходит на узкую фазу для соседних пар (GJK и EPA).
- Не сделано, но запланировано: сохранение контактов между шагами, тёплый старт EPA от прошлой нормали, отсечение пар по AABB до GJK, раскладка данных по массивам (SoA). Пока оптимизация физики не завершена, и требование «до предела» выполнено не полностью.
- Рэгдолл: 369 мкс на кадр для одного персонажа, около 2.2 % бюджета кадра 60 Гц на этом стенде. Сцены с несколькими персонажами в бенчмарке нет. Простая экстраполяция дала бы примерно 7 мс на 20 персонажей в одном потоке, но это не измерено.
- Рендерер OpenGL не измерялся: на стенде нет GPU.

## Игра: бенчмарк `bench/BenchGame.pas`

Запуск: `./build.sh bench` (после бенчмарка движка). Замер - `GetTickCount64`, не менее 0.5 с на каждый.
Стенд тот же: виртуальная машина, 2 vCPU Xeon 2.6 ГГц, один поток, FPC 3.3.1-dev.

| Операция | Время, мкс | Было (до отсева капсулы) |
|---|---|---|
| луч по уровню (17 коробок) | 3.7 | - |
| шаг капсулы `BodyMove` (GJK/EPA), шаг 1/120 с | 27.9 | 39.2 |
| проба у поверхности `BodyProbe` | 6.5 | 6.3 |
| поиск пути A*, сетка 60x60 клеток | 70 | 73 |
| шаг мира: игрок и 3 врага, 1/120 с | 84 | 158 |
| шаг мира: игрок и 16 врагов, 1/120 с | 378 | 706 |
| сборка элементов кадра (164 шт.), без GL | 31 | - |

Оптимизация: `GameBody.Candidate` отсекал коробки по описанной сфере. Сфера пола радиусом 56 м не отсекает
ничего, поэтому пол проверялся GJK/EPA на каждом шаге. Теперь кандидат проверяется расстоянием от трёх точек оси
капсулы до коробки в её локальной системе (запас 0.3 м). Результаты тестов не изменились (132 + 79 проверок).

Оценка: при 120 Гц шаг мира с 16 врагами занимает около 4.5% одного ядра. Основная стоимость - GJK/EPA в
`BodyMove`. Не сделано: кэширование контактов между шагами, сон тел, SoA.

Рендер: на процессоре замерена только сборка элементов кадра. Программный рендер (Mesa softpipe) занимает около
4 с на кадр 960x540 и показателем производительности не является. Нагрузка на GPU не измерялась.

Раздел движка выше не менялся: физика этой сессии не трогалась, цифры остаются действительными.
