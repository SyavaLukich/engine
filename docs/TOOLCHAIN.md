# Тулчейн: FreePascal, собранный из исходников

## Итог

| Параметр | Значение |
|---|---|
| Компилятор | FPC 3.3.1-dev (`fpc -iV` = `3.3.1`) |
| Исходники | `github.com/fpc/FPCSource`, коммит `db4bc06b67660b0d7c18c97533af02b8b2fabbc7` (2019-09-29), архив с `codeload.github.com` |
| Стартовый компилятор (seed) | `ppcx64`, SHA-256 `8f401fd710fa30a3e076e00f5991d70390172d09d77906d2a1face40ff3188c8` |
| Цель | `x86_64-linux` (в сборке также RTL и пакеты `packages/`) |
| Скрипт | `tools/fpc/build_fpc_from_source.sh` |

Бинарный компилятор не используется как рабочий: он нужен только для первой стадии сборки. Итоговый компилятор
собран самим исходным кодом коммита `db4bc06b` в три стадии.

## Как воспроизвести

```sh
FPC_SEED=/путь/к/ppcx64 tools/fpc/build_fpc_from_source.sh
```

Переменные: `FPC_COMMIT` (коммит), `FPC_WORK` (каталог исходников, по умолчанию `~/.local/fpc-src`),
`FPC_PREFIX` (установка, по умолчанию `~/.local/fpc-3.3.1-dev`), `FPC_SEED_SHA256` (ожидаемая контрольная сумма seed).

Скрипт:
1. проверяет SHA-256 стартового компилятора и отказывается работать при несовпадении;
2. скачивает архив коммита и распаковывает его;
3. запускает `make all FPC=<seed> OVERRIDEVERSIONCHECK=1` (штатный cycle FPC: stage1 -> stage2 -> stage3, затем RTL и пакеты);
4. копирует компилятор, RTL и пакетные модули в `$FPC_PREFIX`, пишет `bin/fpc.cfg` с одной строкой `-Fu...`;
5. компилирует и запускает самопроверку: динамические массивы, `SysUtils`, файловый ввод-вывод, код выхода.

## Почему seed и почему `OVERRIDEVERSIONCHECK=1`

- Makefile FPC принимает стартовым компилятором только определённые версии (3.2.0 и 3.0.x). Seed имеет версию 3.3.1
  снимка 2019 года, поэтому без `OVERRIDEVERSIONCHECK=1` сборка останавливается на проверке версии. Это безопасно
  именно здесь: seed и исходники относятся к одному снимку ветки 3.3.1-dev.
- Seed взят из репозитория `zeljkoc/pandroid` (путь `FreePascal/fpc/bin/ppcx64`). Этот бинарник не собирался нами
  и его происхождение проверено только косвенно:
  - сборка с ним даёт неподвижную точку компилятора: `compiler/ppc2` и `compiler/ppc3` совпадают;
  - исходные файлы совпадают с официальной историей: `compiler/pp.pas` (blob `e42021bf`) и `compiler/cpupara.pas`
    (blob `e0e8ebea`) равны версиям из `db4bc06b`.
- В дереве pandroid есть файл, которого нет в официальной истории (`rtl/inc/aliases.inc`, blob `4d1857c1`).
  Поэтому само дерево pandroid не используется: исходники берутся только из официального архива коммита.

## Почему не собрана версия 3.2.2

Попытки собрать стабильную 3.2.2 из исходников не удались, поэтому разработка ведётся на 3.3.1-dev:

- seed 2019 года не собирает RTL 3.2.2 (ошибка `IsManagedType` в `types.pp` и `fgl.pp`; обход через `-dVER3_0` помогает
  только для RTL);
- компилятор 3.2.2 не собирается этим seed: `cpupara.pas` даёт ошибку несовместимых типов
  (`tcpuregisterarray` против `Array[0..7] Of TSuperRegister`);
- цепочка 3.0.4 -> 3.2.0 -> 3.2.2 не проходит: RTL 3.0.4 не собирается seed (`Internal type TVMT does not look as expected`),
  а stage1, собранный самим trunk-компилятором, падает с segmentation fault на `system.pp`.

Официальный релиз 3.2.2 и готовый бинарный пакет FPC с официального сайта в этой среде недоступны (сеть ограничена
GitHub, npm и PyPI). Код написан в переносимом подмножестве Object Pascal (`{$mode objfpc}`), но на 3.2.2 не проверялся.
Проверка на 3.2.2 остаётся задачей для сборки у пользователя.

## Что проверено

- `fpc -iV` возвращает `3.3.1`.
- Самопроверка и тесты проекта (`./build.sh`) проходят на собранном компиляторе.
- Чистая повторная сборка скриптом: см. раздел «Журнал проверки» ниже.

## Журнал проверки

Полная сборка скриптом выполнена дважды: в рабочем каталоге и в отдельном каталоге с нуля (повторная загрузка архива,
распаковка, cycle, установка, самопроверка). Обе сборки завершились кодом 0; лог сборки не содержит ошибок компиляции.
